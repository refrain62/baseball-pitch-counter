# PC-001: 投手ごとのイニング別球数と交代後の訂正

状態: 実装PRレビュー待ち

## 要件

1. 試合のイニングを切り替え、各チーム側・各投手の球数をイニング別に記録する。
2. イニングを切り替えても投手の累計球数を維持する。
3. 投手交代後も交代済み投手の各イニング球数と累計を訂正できる。
4. 現在の投手の記録も確認・訂正でき、合計表示と回別表示を同期する。
5. 既存の `pitch-counter-state-v3` 保存データを維持する。回別情報がない旧累計はイニング未設定分として残し、1回などに誤って割り当てない。

## 操作とデータの扱い

- 各チーム側の「イニング変更」を押すと選択モーダルを開き、1〜9回と延長10〜99回から変更先を選ぶ。モーダルには現在の回と変更先を表示する。
- 「通常」の回一覧の直上に「−／変更先／＋」を横並びで大きく配置する。前後ボタンは1回ずつ変更し、1〜99回の範囲で止める。通常回の一覧は1〜9回だけを表示する。
- 延長回は数値入力と「−／＋」で選ぶ。通常回を選んでいる間は入力欄を空にして「10」をプレースホルダーに表示し、空欄・小数・10未満・99超はエラーを表示して確定させない。
- キャンセルまたは閉じる操作では状態を変更しない。「この回に変更」を確定した後の投球から選択した回へ記録する。イニングは両側で独立して保存し、切り替えても累計球数や投手は変更しない。
- 現在回のチップを色で示す。球を追加・戻す操作は、その側の選択中イニングの球数を更新し、投手の累計へ反映する。
- 投手交代では、現在の投手記録を履歴へ移し、新しい投手を0球から記録する。
- 現在投手の回別チップ、または交代済み投手の履歴を開くと、投手累計と回別の球数を確認できる。チップを押すと対象回だけを±操作または数値入力で訂正でき、保存時に累計を再計算する。
- イニング別カードは投球数が1球以上ある回だけ表示する。0球の回はカードを表示せず、表示対象がない場合はイニング別カードの一覧領域も表示しない。記録データと現在イニングは保持する。
- 旧データの「イニング未設定分」も独立したチップから訂正できる。
- 左右の個別リセットは確認後、現在投手の全回別球数とイニング未設定分を消去し、投手交代履歴を保持する。全リセットは確認後、両側の投手別記録・交代履歴・チーム名・イニングを初期化する。
- 投手1人あたりの累計は999球まで、編集できる投手履歴は各側の直近100人までとする。100人を超える保存履歴は最大900人分を保持するが、表示・編集対象にはしない。異常に大きい保存配列は最大1,000人分までを読み込み、超過分は読み込み対象外として画面に注記する。
- 変更前の保存データで共有していた現在イニングは、移行時に両側それぞれの初期イニングとして引き継ぐ。
- データは既存どおりブラウザーの `localStorage` に保存し、サーバーには送信しない。

## 画面設計・レスポンシブ表示

- 添付された画面案に沿い、濃紺を基調に1塁側を青、3塁側を赤で示す2カラム構成を維持する。
- 「イニング変更」は「選手交代」の直上に、既存アクションと揃えた横幅で配置する。選択モーダルは画面内に収め、回の選択肢をスクロール可能にする。キーボードでは左右矢印で1つ、上下矢印で表示列数分移動し、Home、Endで先頭・末尾へ移動できる。
- 投球数訂正ダイアログは画面幅の94%以内かつ最大520pxとし、PCで内容を横にはみ出させない。各訂正行は左に対象ラベル、右に「−／数値／＋」を並べる。
- 320〜360px幅でも訂正行の横並びを維持し、320px未満では縦積みに切り替えて横はみ出しを防ぐ。
- 回の選択肢は44×44px以上、投球数訂正の「＋／−」ボタンは56×56px以上とし、白背景・濃い大きな記号・側ごとのアクセント枠と影で目立たせる。「−／変更先／＋」の操作は最小80×64pxとする。延長回の前後ボタンも白系の背景で統一する。

## 完了条件

- 現在投手・交代済み投手の記録で、累計が回別球数と未設定分の和に一致する。
- 過去のイニングへ戻って訂正しても、後続イニングの記録が失われない。
- 旧形式の保存データを読み込んだとき、旧累計を保持しながら回別情報を捏造しない。
- イニング選択モーダルで、変更先の前後移動・通常回一覧・延長入力が同期し、不正な延長入力を確定できない。
- `pnpm test` と `pnpm build` が成功する。
